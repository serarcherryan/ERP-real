# Security And Compliance

## 1. 安全基线

- 所有接口默认需要认证，公开接口必须显式声明。
- 所有业务查询默认需要租户隔离。
- 高敏感数据访问必须审计。
- 角色权限和数据权限分离设计。
- 后台管理操作必须记录操作者、时间、IP、来源端、变更前后值。
- 文件上传必须校验类型、大小、病毒扫描和访问权限。
- 导出任务必须记录导出人、范围、原因和文件过期时间。

## 2. 权限模型

```text
User -> Role -> Permission
User -> DataScope -> Tenant/Facility/Department/Resident
```

当前落地实现：

- 后台账号存储在 `sys_users`，密码以 BCrypt hash 存储。
- `POST /api/v1/auth/login` 校验用户名密码后签发 8 小时 JWT。
- JWT claims 包含 `userId(sub)`、`displayName`、`role`、`tenantId`、`facilityId`。
- Web 管理端把 `token` 和 `user` 保存到 `localStorage`，后续请求通过 `Authorization: Bearer <token>` 访问后端。
- 后端 `AuthFilter` 解析 JWT 并写入 `AuthContext`，业务模块通过 `RequestContext` 获取租户、机构、角色和操作者。
- `dev/test` 保留静态 token fallback 用于联调；生产不得依赖静态 token。

权限判断至少包含：

- 功能权限：能不能操作
- 数据权限：能操作哪些租户、机构、部门、老人
- 字段权限：能不能看手机号、身份证、健康记录、财务数据
- 场景权限：是否在值班、是否为负责护理区、是否为家属绑定老人

## 3. 数据分类

| 级别 | 数据 | 处理要求 |
| --- | --- | --- |
| 普通 | 公共配置、字典 | 基础访问控制 |
| 敏感 | 员工信息、库存、排班 | 权限控制、审计 |
| 高敏感 | 老人档案、家属联系方式、财务 | 脱敏、审计、导出限制 |
| 极高敏感 | 医疗记录、用药、身份证 | 强权限、全量审计、最小化展示 |

## 4. 审计事件

| 事件 | 是否必须 | 内容 |
| --- | --- | --- |
| 登录失败 | 是 | 用户、IP、原因 |
| 登录成功 | 建议 | 用户、角色、来源端 |
| 查看高敏感数据 | 是 | 用户、资源、原因、范围 |
| 修改老人档案 | 是 | 前后值、操作者 |
| 修改护理/医疗记录 | 是 | 前后值、复核信息 |
| 导出数据 | 是 | 条件、数量、文件、过期时间 |
| 跨租户访问 | 是 | 来源、目标、审批依据 |

## 5. 安全评审清单

- 是否存在 IDOR 越权风险
- 是否所有查询都带租户/机构过滤
- 是否有字段级脱敏
- 是否有批量导出限制
- 是否有幂等和重放防护
- 是否有操作审计
- 是否处理上传文件风险
- 是否避免在日志中输出敏感字段
- JWT secret 是否来自安全配置，且生产环境不使用开发密钥
- 登录失败是否有限流、告警或账号锁定策略
