# 满血版部署方案（企业级云原生高可用架构）

该方案适用于多院区连锁、高并发、强合规监管（如数据审计要求）、对停机零容忍的生产环境。依托云厂商（如阿里云、AWS 等）的原生组件与 Kubernetes 实现微服务化的高可用治理。

## 架构拓扑

               |

## 核心组件说明与企业级最佳实践

### 1. 前端层（分离式无服务器架构）
* **Web-Admin 端**：无需部署 Nginx 服务器。通过 CI/CD 构建出 `dist` 后，直接推送到云上的**对象存储（OSS/S3）**并开启静态网站托管，配合 CDN 绑定域名提供全球就近访问。这种方式成本极低，且承载极高并发没有带宽瓶颈。
* **小程序端（家属/员工小程序）**：通过 CI 自动调用微信开发者工具 CLI 完成上传、发布审核闭环。

### 2. 后端核心层（云原生容器化 Kubernetes）
* **无状态设计**：确保 Spring Boot 服务内不缓存任何会话和状态（全部走 JWT + Redis），这使得集群可以自由增减节点。
* **弹性伸缩 (HPA)**：在 Kubernetes 集群（例如阿里云 ACK 或 AWS EKS）中，针对 Backend 应用配置 CPU 阈值（如大于 70%）。系统将在遇到如清晨集中打卡、查房等突发高流量时自动加开 Pod，并在低峰期释放。
* **平滑发布**：基于 K8s Service 实现滚动更新（Rolling Update），新版本无缝替换老版本，用户对部署过程零感知。

### 3. 数据隔离与持久化
* **高可用 RDS 数据库**：采用双节点以上的 RDS PostgreSQL。主库故障时，底层存储秒级将 VIP（虚拟IP）切换至备库，实现数据容灾 RPO=0。
* **自动化数据迁移**：通过集成 Flyway，在 CI/CD 阶段由独立 Job 预先执行 `db/migration/*.sql` 脚本变更数据库结构，确保业务 Pod 启动时数据库结构完全合法。
* **直接签发直传机制**：无论是无人机大体量的监控回传录像，还是护理人员上传照片附件，**绝对不经过**后端服务器中转。后端仅签发限时的临时访问凭证 (STS)，由客户端利用凭证向大带宽的云端对象存储直传，释放后端宽带。

### 4. 物联网通信层（EMQX 企业集群版）
* 针对无人机或病床监护仪的高频遥测和 OSD（On-Screen Display）数据流，构建 EMQX 分布式高可用集群。
* 搭配一个 TCP 四层内网/外网负载均衡器承接设备的 MQTT 连接。通过配置 EMQX 的规则引擎，将业务数据直接流转至 Webhook、Kafka 甚至时序数据库。

## 安全与可观测性体系

1. **监控告警 (Monitoring)** 
   使用云厂商全托管的 Prometheus 集成 Grafana。采集并监控 Kubernetes 集群 Node 指标、Spring Boot JVM 的 GC 与线程指标，配置飞书/钉钉的触发告警机器人。
2. **中心化日志收集 (Logging)** 
   应用日志通过 stdout 输出，由 Fluent-bit 采集代理通过内网统一发送到 Elasticsearch / 阿里云 SLS 中。开发与运维团队通过聚合面板快速通过 `traceId` 检索完整的调用链和日志。
3. **安全合规管控 (Security & Compliance)** 
   * **网络隔离**：云基础设施利用 VPC (私有云网络) 隔绝所有内外网组件。RDS、Redis、K8s Node 等内网互通且不绑定公网 IP。只在外部流量接入点（ALB/NAT 网关）暴露。
   * **数据保护**：开启数据库 SQL 防注入监控、SQL 慢查询审计。应用层面，密码以强哈希保存，所有的 API 调用携带多租户隔离标识并在网关处统一阻断越权。

## 从“性价比版”到“满血版”的平滑演进策略

此 ERP 系统良好的模块化架构，使得架构演进能够分阶段无痛完成：
1. **外包数据库**：将单台服务器中的 PostgreSQL Dump 后迁移至云端 RDS 实例。修改后台 `application.yml` 数据源连接串，完成数据层的上云。
2. **前端切流**：将 Nginx 部署的前端产物推入 OSS，域名 CNAME 直接切换到 OSS+CDN 提供服务，彻底释放原服务器 CPU。
3. **全面容器化**：最后，把 Spring Boot API 迁移进 K8s 集群，原性价比服务器此时可直接销毁，系统完成向企业级云原生的涅槃。
