# ADR-0001: Platform Architecture

| 字段 | 内容 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-04-25 |

| 影响范围 | 后端架构、模块边界、部署方式、中间件选型 |

## Context

智慧养老平台需要同时支持 Web 端、小程序端、物业条线、养老中心条线、用户/家属和管理驾驶舱。首期重点是长者档案管理、工单管理和数据驾驶舱，但后续会继续扩展健康管理、活动管理、物资管理、关怀沟通、消息通知和审计合规。

系统具有以下约束：

- 业务模块多，生命周期长，需要清晰的数据所有权和模块边界。
- 长者档案、健康、家属联系方式等数据敏感，需要严格权限、脱敏和审计。
- 后续存在工单高峰、驾驶舱高频刷新、消息提醒风暴和报表导出等高并发场景。
- 当前处于前期建设阶段，需要避免过早微服务化带来的交付和运维复杂度。

## Decision

采用 Java 21 + Spring Boot 3 + Spring Modulith 构建模块化单体。系统按领域模块划分边界，前期统一部署，后期按压力和组织边界拆分为独立服务。

核心中间件选择：

- PostgreSQL 作为核心交易库。
- Redis 作为缓存、幂等、限流和权限缓存组件。
- Kafka 或 RabbitMQ 作为异步事件和削峰组件。
- ClickHouse 承载数据驾驶舱和报表分析。
- OpenSearch 承载全文检索。
- MinIO / S3 兼容对象存储承载附件、报告和导出文件。

## Options Considered

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 模块化单体 | 交付快、事务简单、部署和调试成本低、边界可通过模块约束沉淀 | 需要严格治理，避免演化成无边界单体 | 采纳 |
| 全量微服务 | 独立扩容、服务边界天然清晰 | 前期复杂度高，分布式事务、运维和链路排障成本高 | 暂不采纳 |
| 传统三层单体 | 上手快 | 模块边界弱，后期拆分成本高 | 不采纳 |
| Serverless / BaaS | 弹性好、运维轻 | 复杂权限、审计、状态机和私有化部署适配风险高 | 不采纳 |

## Consequences

- 正面影响：首期能快速交付长者档案、工单和驾驶舱，同时保留服务拆分路径。
- 负面影响：需要通过代码规范、模块依赖检查和 Harness 文档防止跨模块直接写入。
- 成本：需要建设统一认证、租户隔离、审计、事件发布、监控和 CI 检查。
- 后续工作：建立模块包结构、定义跨模块 API 和事件契约、补充模块级测试。

## Validation

- 如何证明这个决策有效：首期模块能在同一后端内交付，并通过模块边界测试、契约测试和权限测试。
- 需要观察的指标：接口 P95、数据库慢查询、队列积压、模块间违规依赖数量、审计覆盖率。
- 需要复盘的时间点：首期 MVP 上线后、工单 QPS 或驾驶舱查询压力达到容量阈值时。
