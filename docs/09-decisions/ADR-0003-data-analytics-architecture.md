# ADR-0003: Data Analytics Architecture

| 字段 | 内容 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-04-25 |
| 决策人 | TBD |
| 影响范围 | 数据驾驶舱、报表、事件同步、分析库、导出任务 |

## Context

数据驾驶舱需要展示入住率、房态、长者年龄/性别/疾病分类、活动参与率、服务频次、工单数量、待办超时和趋势指标。若这些聚合查询直接访问 PostgreSQL 业务主库，在并发升高时会影响长者档案、工单和入住等核心交易链路。

系统还需要支持报表导出、指标下钻、跨机构汇总和管理层高频刷新，因此分析查询必须与在线交易写入解耦。

## Decision

采用 PostgreSQL + MQ/CDC + ClickHouse 的分析架构：

- PostgreSQL 保存核心交易数据。
- 业务模块发布领域事件，或通过 CDC 同步必要变更。
- 数据中心消费事件，生成指标快照和分析宽表。
- ClickHouse 承载驾驶舱查询和报表聚合。
- 报表导出通过异步任务生成文件，文件存储到 MinIO / S3。

驾驶舱禁止直接扫描业务主库做复杂聚合。必要的在线小指标可通过 Redis 缓存或 PostgreSQL 物化视图承载，但必须有容量评估。

## Options Considered

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| PostgreSQL 直接聚合 | 实现最简单，数据实时 | 高并发和复杂统计会拖慢交易库 | 不采纳 |
| PostgreSQL 物化视图 | 运维简单，适合小规模指标 | 跨维度、长周期和高并发查询能力有限 | 局部使用 |
| ClickHouse 分析库 | 聚合查询快，适合驾驶舱和报表 | 需要同步链路和口径治理 | 采纳 |
| 外部 BI 平台 | 功能丰富 | 权限、嵌入、私有化和数据治理复杂 | 后续评估 |

## Consequences

- 正面影响：保护核心业务库，驾驶舱可独立扩容，报表和趋势查询性能更稳定。
- 负面影响：指标存在分钟级最终一致，需治理指标口径和数据延迟。
- 成本：需要事件消费、重算任务、数据校验、分析库运维和指标版本管理。
- 后续工作：定义指标字典、事件契约、宽表模型、重算机制和导出审计。

## Validation

- 如何证明这个决策有效：驾驶舱查询不影响业务库 P95，指标刷新延迟满足目标。
- 需要观察的指标：ClickHouse 查询 P95、消费延迟、死信数量、指标重算耗时、业务库慢查询数量。
- 需要复盘的时间点：驾驶舱首发后、指标数量扩展到 20 个以上或跨机构汇总压力明显上升时。
