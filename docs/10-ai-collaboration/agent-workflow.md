# AI And Engineering Collaboration Workflow

## 1. 目标

让 AI Agent、工程师、产品和测试在同一套边界下协作，避免需求漂移、重复实现、无测试变更和隐性架构债务。

## 2. 给 AI Agent 的任务输入模板

```text
目标:
业务背景:
影响模块:
影响端:
必须遵守的契约:
不可修改范围:
验收标准:
需要补充的测试:
风险点:
```

## 3. AI 开发前检查

- 先读取相关模块设计文档。
- 查找已有实现和命名风格。
- 明确是否涉及权限、审计、租户隔离、数据迁移。
- 涉及跨模块调用时，先检查 API 或事件契约。
- 不清楚业务规则时，补充问题或写出假设。

## 4. AI PR 输出要求

```text
变更摘要:
影响范围:
验证方式:
权限/审计影响:
性能影响:
数据迁移:
回滚方式:
遗留风险:
```

## 5. 禁止事项

- 未读模块设计就跨边界改数据。
- 直接绕过 owning domain 修改其他模块数据。
- 在日志中输出身份证、手机号、病历、支付信息等敏感数据。
- 未说明原因就引入新框架或新基础设施。
- 未补测试就修改核心状态机、金额、权限或多租户逻辑。
